# FORSTICK 이슈 기록

프로젝트를 진행하며 겪은 문제, 내린 결정, 남은 한계, 환경 설정 주의점을 모았다.
서버 주소·접속 방법 같은 비공개 정보는 이 문서에 넣지 않는다(별도 비공개 문서).

정리일: 2026-10-16

---

## 1. 트러블슈팅

### 1-1. 연결이 끊겨도 화면에 '정상'으로 표시됨 (프론트, `fbad967`)
- 문제: 서버 연결이 끊겨도 상태 위젯이 마지막 값으로 '정상'을 보여 줬다.
- 원인: 받지 못한 값을 '문제 없음'으로 간주했다.
- 해결: 연결이 정상이 아니면 '정상'을 표시하지 않는다. 회귀 점검 10항목, 새 테스트 8개(수정 전 코드에서 실패 확인).

### 1-2. 출발지와 목적지가 뒤바뀐 계획이 검사를 통과함 (백엔드, `a37909d`)
- 문제: 줄여 말한 지시에서 AI가 집는 곳과 놓는 곳을 바꾼 계획을 만들었는데 검사를 통과했다.
- 원인: 계획 안에 지시한 장소가 들어 있는지만 보고, 각 장소가 출발지인지 목적지인지는 비교하지 않았다.
- 해결: 집는 단계는 지시한 출발지와, 놓는 단계는 지시한 목적지와 각각 맞춰 본다. 뒤바뀐 계획은 모두 막히고, 계획을 못 만들던 줄임말 지시 6개도 계획이 만들어지게 됐다.

### 1-3. Gazebo 화면 프레임이 낮음 → 3D 관측 화면으로 교체
- 문제: 대시보드의 Gazebo 카메라 영상이 끊겨 보였다(실측 약 5.6장/초).
- 원인: AI 모델과 Gazebo를 함께 띄우니 렌더링 프레임이 나오지 않았다(멘토링 정리 기준).
- 해결: 서버는 관절·자재 위치 같은 관측값만 보내고, 브라우저가 Three.js로 그린다. Gazebo 영상은 3D를 못 받을 때의 대체 화면으로 남겼다.

### 1-4. 평가 스크립트가 운영 중인 로봇에 정지 명령을 보냄 (`cad42b5`)
- 문제: 명령 평가를 돌리는 동안 운영 중인 시뮬레이션 로봇에 정지가 12번 갔다(그 시간 실행 중인 작업이 없어 피해 없음).
- 원인: 평가기는 "실행은 호출하지 않는다"고 돼 있었지만, 정지는 실행과 다른 경로라 빠져 있었다.
- 해결: 평가 중 정지는 기록만 하도록 고쳤다. 고친 코드가 서버 PC에 합쳐지기 전에는 운영 시간에 평가를 돌리지 않는다.

### 1-5. 관절 한계 시험에서 팔이 움직이지 않음
- 문제: 명령은 맞는데 팔이 한계 근처에서 멈췄다. 이틀간 제어기 한계 설정 탓으로 잘못 짚었다.
- 원인: 시험 환경. 팔을 바닥 높이에 생성해 손목이 바닥에 닿았고, 중력이 관절을 한계 쪽으로 눌러 잠겼다.
- 해결: 중력을 끈 조건에서 12/12 통과(속도·위치 한계 모두 넘지 않음).
- 교훈: "명령은 맞는데 안 움직임"이면 제어 설정보다 접촉·중력을 먼저 의심하고, 조건 하나만 바꾼 비교 실험으로 확인한 뒤 단정한다.

### 1-6. 마이크가 동작하지 않음
- 원인: 브라우저는 HTTPS(또는 localhost)에서만 마이크를 허용한다.
- 해결: HTTPS로 감싸는 실행 스크립트(`scripts/run_web_tls.sh`, 자체 서명 인증서)를 쓴다.

### 1-7. 발표 HTML의 시연 영상이 재생되지 않음
- 원인 1: 원본 영상이 HEVC(H.265)라 일부 브라우저가 재생하지 못한다.
- 원인 2: 영상을 HTML에 내장하면 페이지 스크립트보다 먼저 로드가 끝나, '준비됨' 이벤트를 놓쳐 화면에 안 나타났다.
- 해결: H.264로 다시 인코딩(`ffmpeg -c:v libx264 -crf 21 -pix_fmt yuv420p -movflags +faststart`)하고, 스크립트에서 `readyState`를 한 번 더 확인한다.

### 1-8. 3D 시뮬레이션 칸 둥근 모서리에 진한 선
- 원인: 3D 캔버스 뒤의 어두운 영상 칸 배경이 둥근 모서리 경계에서 비쳤다.
- 해결: 3D 화면이 깔리면 배경을 빼고, 연결 중일 때만 스피너 덮개가 어두운 배경을 칠한다.

### 1-9. Windows에서만 실패하는 테스트
- 문제: 리눅스(WSL) 기준으로 짠 테스트 6건(9/30), 10건(10/2)이 Windows와 새로 받은 저장소에서 실패했다.
- 해결: 테스트 쪽을 고쳤다(제품 동작 변경 없음).

### 1-10. README에 비공개 평가 문장이 들어감
- 문제: README 예시로 쓴 문장이 성능 평가용 비공개 시험 문장이었다.
- 발견: 저장소의 평가 데이터 검사 스크립트(`scripts/check_workcell_eval_dataset.py`)가 누출로 잡았다.
- 해결: 예시를 문장 인용 없이 설명으로 바꿨다. 문서를 고친 뒤에는 이 검사를 돌린다.

### 1-11. 발표 HTML을 다시 생성해 직접 고친 내용이 사라짐
- 문제: 생성 스크립트로 발표 파일을 다시 만들면서 손으로 고친 그래프·영상이 덮어써졌다.
- 해결: 이전 버전에서 복구. 이후 최종 HTML 파일을 원본으로 보고 직접 고친다.

## 2. 결정과 그 이유

| 결정 | 이유 |
|---|---|
| AI는 계획만 만들고, 실행 여부는 규칙 검사와 사람이 정한다 | 언어모델 출력은 확률적이라 잘못 알아들은 지시가 그대로 로봇 동작이 될 수 있다 |
| 텍스트로 정확히 입력한 명령도 확인 카드를 거친다 | 입력 방식과 관계없이 실행 전 사람 확인을 한 가지 흐름으로 맞춘다 |
| "멈춰"는 AI 해석을 거치지 않고 바로 정지, 정지는 로그인 없이 받는다 | 정지가 AI 응답·로그인 만료 때문에 늦어지면 안 된다 |
| 정지 버튼을 명령 패널에서 빼고 헤더로 옮김, 이름은 "즉시 정지" | 명령 패널 안에서는 실수로 누르기 쉽다. "비상정지"는 물리 비상정지 장치 상태 표시에만 쓴다 |
| 구글 로그인만, 미리 등록된 계정만 통과 | 회원가입 없이 관리자가 계정을 관리한다. 세션 12시간 |
| 화면에 '시뮬레이션' 상시 배지는 두지 않음 | 사용자 결정. 서버는 시뮬레이션 여부 값을 계속 보내고 표시만 뺐다. 실제 로봇 연결 전이나 외부 공유 때 다시 검토 |
| 대시보드 라이트 테마, 버튼은 처음 만든 초안(A) | 여러 안을 비교한 뒤 첫 초안이 가장 자연스러웠다 |
| 화면설계서 기능은 MVP로 줄이지 않고 전부 구현 | 설계한 기능을 최대한 구현하는 방향 |
| 요구사항 판정 기준은 현재 구현 | 기획 이후 바뀐 구성(로봇·모델·화면)은 실패가 아니라 기획서 갱신 대상 |
| 로봇을 실제로 움직이는 검사는 담당 팀원 허락 뒤에만 | 공용 작업 셀 PC를 다른 사람이 쓰는 중일 수 있다 |
| 서버는 웹 프레임워크 없이 ASGI를 직접 사용 | 경로가 10여 개라 의존성을 늘리지 않는 쪽이 단순하다 |
| DB는 SQLite, 저장 계층 분리 | 작업 셀 1개에는 충분하다. 여러 셀 통합 때 PostgreSQL 구현을 추가할 수 있게 했다 |
| 음성 인식 고도화(사투리 등)는 하지 않음 | 멘토링 결론: 프로젝트 목적은 로봇 제어, 음성은 기존 모델 활용 |
| 코드 검사는 AI 규칙 문서가 아니라 프로그램(`scripts/check.sh`)으로 | 팀원마다 쓰는 AI가 달라 규칙 문서만으로는 일관성을 지키기 어렵다 |

## 3. 남은 문제와 한계

- **정상 지시 오차단 17.1%** (목표 10% 이하). 위치 이동 지시를 자재 이송으로 오해하는 경우가 많다.
- **애매한 지시 되묻기 65.6%** (목표 80%), **정상 지시 되묻기 22.9%** (목표 15% 이하). 근거: 2026-10-08 평가.
- **정지까지 걸리는 시간은 측정하지 않았다** (목표: 버튼 0.2초, 음성 0.5초).
- 실제 로봇 미연동. 시뮬레이션(Gazebo)에서만 동작한다.
- 로봇 기종은 FR3 한 종류, 작업 셀 1개만 기록한다.
- 대시보드 전체화면의 '정지 확인' 화면은 아직 서버 값과 연결되지 않은 목업이다(실제 정지 버튼으로는 열지 않음).
- 평가 데이터 검사에서 '추출 정답 불일치 6건'이 계속 나온다(원인 미확인).
- 저장소 저장 테스트(`test_storage_roundtrip`)가 Windows에서 실패한다(테스트 쪽 문제로 판단, 팀원에게 전달 필요).
- 커밋 전 검사가 이 PC에 없는 `md/` 문서 경로 5건 때문에 항상 실패한다(`md/`는 git에 올리지 않는 폴더).
- 팀 저장소: `feature/sim-overlay-ux`와 `master`를 합치면 `README.md`가 충돌한다. 서버 PC에는 GitHub에 올리지 않은 팀원 커밋이 있어, 서버 PC에는 필요한 커밋만 골라서(cherry-pick) 반영한다.

## 4. 환경 설정 주의점

| 상황 | 해결 |
|---|---|
| WSL2에서 vLLM이 `UVA is not available`로 죽음 | `VLLM_WSL2_ENABLE_PIN_MEMORY=1` |
| vLLM 컴파일 단계에서 `ninja`를 못 찾음 | venv의 `bin`을 PATH 앞에 둔다 |
| GPU 8GB에서 모델이 안 뜸 | `--max-model-len 3072 --gpu-memory-utilization 0.86` |
| Codex CLI 기본 모델이 400 오류 | `codex exec -m gpt-6-sol ...`로 모델을 지정 |
| Codex에 프롬프트를 인자로 주면 끝없이 멈춤 | 프롬프트를 stdin(`-`)으로 넘기거나 `< /dev/null`을 붙인다 |
| Windows에서 파이썬이 한글 경로·파일을 깨뜨림 | `PYTHONUTF8=1`을 주고, 셸 heredoc 대신 스크립트 파일로 실행 |
| Windows에서 `python3`가 다른 버전을 가리킴 | `PYTHON=python ./scripts/check.sh` |
| Playwright 기본 Chromium이 H.264 영상을 못 틂 | `channel: 'chrome'`(설치된 Chrome)으로 실행 |
| 영상이 HEVC라 브라우저·PPT에서 안 나옴 | ffmpeg로 H.264 변환(1-7 참고) |
| 화면 확인은 배포 형태로 | `npx vite build` 후 nginx로 확인. scoop의 nginx `current` 경로가 깨질 수 있어 버전 폴더의 `nginx.exe`를 직접 실행 |
| 영상 분석 스킬(watch) | yt-dlp와 ffmpeg를 PATH에 추가. ffmpeg 9에서 `-vsync`가 없어져 `-fps_mode`로 수정 필요 |
| git이 LF/CRLF 경고를 냄 | 동작에는 영향 없음 |
| GitHub 원격 두 개 | `origin` = 팀 저장소, `mine` = 본인 저장소(SUECREAM00/Forstick). 본인 저장소에 올릴 때는 `git push mine` |
| 커밋 전 검사가 `md/` 경로 5건으로 실패 | 그 5건뿐이면 `--no-verify`로 커밋(사용자 허락) |
