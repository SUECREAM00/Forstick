# 포스틱(FORSTICK) 상태 매트릭스

화면설계서(`기획서_템플릿(포스틱).md` 2. 화면설계서)에 산문으로 정리된 규칙을 `조건 → 표시 → 허용행동` 형태로 정규화한 문서. AI 프로토타입 생성, 개발 구현, 테스트케이스 작성 시 이 문서를 기준으로 삼는다. 산문 문서는 "왜 이렇게 했는지" 근거를, 이 표는 "구현 시 조건 분기"를 담당하며 서로 대체 관계가 아니다.

## 1. 로봇 카드 — 상태 5단계

| 조건 | 표시 | 허용행동 |
|---|---|---|
| `status = NORMAL` | 색: 기본톤 / 모양: ● 원형 | 명령 입력 가능 |
| `status = NOTICE`(알림) | 색: 청색계 / 모양: ◆ 마름모 | 명령 입력 가능, 알림목록에 항목 추가 |
| `status = WARNING`(경고) | 색: 황색계 / 모양: ▲ 삼각형, 카드 테두리 강조 | 명령 입력 가능(확인단계 강화), 알림목록 등록 |
| `status = CRITICAL`(위험) | 색: 적색계 / 모양: ■ 사각형, 카드 강조 최대 | 신규 명령 차단, 긴급배너 트리거 |
| `status = NO_DATA`(데이터없음) | 색: 회색 / 모양: ? / "마지막 수신: n초 전" 표시 | 명령 입력 차단, 연결상태 규칙(§7) 적용 |

## 2. 안전 상태 3종 — 비상정지 · 보호정지 · 가드

| 조건 조합 | 카드 1차 표시(요약배지) | 하위 행 표시 | 허용행동 |
|---|---|---|---|
| 3종 모두 OFF | (표시 없음, 정상 배지만) | — | 명령 가능 |
| `guard = ON`만 | "가드 작동중" | 가드만 강조 | 명령 가능(가드 해제 후 진입 동작 제한) |
| `protectiveStop = ON` | "정지됨 · 보호정지" | 보호정지 강조, 나머지 OFF 표시 | 신규 명령 차단, "리셋" 버튼 노출 |
| `eStop = ON` | "정지됨 · 비상정지" | 비상정지 강조 | 신규 명령 완전 차단, UI 정지요청과 시각적으로 구분(§9 STOP경계), 현장 리셋 필요 안내만 표시(원격 해제 버튼 없음) |
| 2종 이상 동시 ON | "정지됨 · 외 N건" + 최고위험 1건 대표 | 3종 모두 개별 표시 | 최고위험 기준 허용행동 적용(비상정지 > 보호정지 > 가드 우선순위) |

## 3. 연속값 요약 — 관절온도 · 부하 등

| 조건 | 표시 | 허용행동 |
|---|---|---|
| `value < warnThreshold` | "정상" 배지만 | 원시값 숨김 |
| `warnThreshold ≤ value < limitThreshold` | "주의" 배지 + 실제값/기준값 병기(예: 78°C / 80°C) | 원시값 노출 시작, 명령은 가능 |
| `value ≥ limitThreshold` | "위험" 배지 + 실제값/기준값 병기 | 해당 관절 관련 신규 동작 차단 |
| 진단/유지보수 화면 조회 시 | 항상 원시값 전체 노출 | — |

## 4. 시뮬레이션 검증 — 판정 결과 신선도

| 조건 | 표시 | 허용행동 |
|---|---|---|
| `result = PASS` AND `now < expires_at` AND `plan_id = current` | "안전 확인됨" 배지 + 최소이격거리 + 검증시각(plan_id는 기술정보에서만) | 실행 버튼 활성 |
| `result = BLOCK` | "실행 차단" 배지 + 사유 전체 문장(코드는 기술정보에서만) | 실행 버튼 비활성, 재계획 유도 |
| `result = BLOCK` AND 추천 수정안 생성됨 | 위 표시 + "추천 수정안: {문장}" 카드 노출 | "이 수정안 적용" 클릭 시 명령 입력창에 텍스트만 채움(제출 아님) — 사용자가 확인 후 별도로 제출해야 새 계획 생성·형식·안전·기하 3단계 재검증 시작. 버튼이 실행까지 이어지지 않음(§9와 동일하게 최종점검에서 사람 재승인 필요) |
| `result = ASK` | "추가 확인 필요" + 질문 옵션 목록 표시 | 실행 대기, 답변 필요 |
| `now ≥ expires_at`(결과 만료) | "검증 만료" 경고 | 실행 버튼 잠금, 재검증 요구 |
| `plan_id ≠ 실행요청 plan_id`(불일치) | "계획 불일치" 경고 | 실행 버튼 잠금 |
| 영상 스트림 끊김 | "영상 끊김 — 판정결과는 유효/무효 별도표시" | 판정결과 자체가 유효하면 실행은 가능(영상은 증거자료일 뿐) |
| 공유구역 영향 있음 | 2셀 화면/평면도 자동 확장 | — |

## 5. 알림 3단계

| 조건 | 표시 위치 | 허용행동 |
|---|---|---|
| `level = TASK`(작업알림) | 명령패널 내부만 | 다른 화면에 노출 안됨 |
| `level = WARNING`(경고) | 카드 강조 + 알림목록 | 확인 시 목록에서 상태 전환(§8) |
| `level = EMERGENCY`(긴급) | 전체폭 배너, 정지버튼 비가림 | 원인해결 전 닫기 불가, "인지확인"으로 축소만 가능 |

**§1(로봇카드 상태 5단계)과의 관계**: §1의 `NOTICE`는 로봇 1대의 종합 상태 배지이고, 여기 §5의 `level`은 개별 알림 이벤트의 등급이다. 서로 다른 분류축이지만 대응 관계는 다음과 같다 — `TASK` 알림 발생 시 해당 로봇 카드는 `NOTICE`로, `WARNING` 알림은 카드 `WARNING`으로, `EMERGENCY` 알림은 카드 `CRITICAL`로 반영된다. 한 로봇에 여러 알림이 동시에 걸리면 카드는 그중 가장 심각한 등급을 표시한다.

## 6. 긴급배너 — 동시발생 집계

| 조건 | 표시 | 허용행동 |
|---|---|---|
| `emergencyCount = 1` | 단일 배너, 로봇명+사유 | 해당 건 상세로 이동 |
| `emergencyCount > 1` | "긴급 N건" + 최고위험 1건 대표 | 클릭 시 로봇별 목록 확장 |
| 인지확인 처리됨 but 미해결 | 배너 축소(완전제거 아님) | 안전회로 복구 전까지 재확대 가능 상태 유지 |
| 안전회로 복구 확인 | 배너 제거 | — |

## 7. 연결상태 · 데이터 신선도

| 조건 | 표시 | 허용행동 |
|---|---|---|
| `age(lastReceived) < 1s`(정상) | 표시 없음(암묵적 정상) | 전체 기능 정상 |
| `1s ≤ age < heartbeatTimeout` | 수신시각 옅게 표시 | 정상 |
| `age ≥ heartbeatTimeout`(단절) | "연결끊김, N초 전 데이터" 전역 경고 | 신규 명령·실행 잠금, 조회만 가능 |
| 재연결 시 | "동기화 중" 표시 후 스냅샷 갱신 | 갱신 완료 전까지 명령 잠금 유지 |

## 8. 알림 생명주기 (경고 이상)

| 상태 | 의미 | 다음 전이 조건 |
|---|---|---|
| `발생` | 조건 최초 감지 | 작업자가 확인하면 `확인`으로 |
| `확인` | 담당자가 인지, 경과시간 카운트 시작 | 대응 시작하면 `조치중`, 미확인 지속 시 escalation |
| `조치중` | 담당자·권고조치 기록됨 | 원인 해소되면 `해결` |
| `해결` | 안전회로 복구/원인 제거 확인됨 | 목록에서 종료 처리 |
| `확인` 상태에서 일정시간 경과 | — | 상위 담당자로 escalation, 배너 재확대 |

## 9. STOP · 제어권 · 운전모드

| 조건 | 표시 | 허용행동 |
|---|---|---|
| UI 정지 버튼(소프트 STOP) 클릭 | "정지 요청됨" (물리 E-stop과 시각적으로 다른 아이콘/색) | 실행 취소 요청 전달, 물리 안전장치 대체 아님을 명시 |
| `mode = REMOTE` AND `owner = 없음` | "제어 가능" | 명령 시도 시 lease 획득 |
| `mode = REMOTE` AND `owner = 본인` | "제어중(본인)" | 명령 가능 |
| `mode = REMOTE` AND `owner = 타인` | "제어중 — {작업자명}" | 명령 버튼 비활성, "인계 요청" 버튼만 노출 |
| `mode = TEACH` or `LOCAL` | "현장 직접조작 모드" | 원격 명령 전체 차단 |
| `lease.expires_at` 만료 임박 | "제어권 만료 임박" | 연장 또는 자동 반납 안내 |

## 10. N대 확장 — 카드그리드 / 타겟선택

| 조건 | 표시/컴포넌트 | 허용행동 |
|---|---|---|
| `robotCount ≤ 6` | 카드 그리드 | 카드 클릭으로 상세 이동 |
| `7 ≤ robotCount` | 목록/표 뷰(사용자가 카드뷰로 전환 가능) | 상태별 정렬·필터 |
| `targetCount ≤ 6`(명령패널) | Chip 나열 | 클릭 선택 |
| `targetCount > 6` | 검색가능 콤보박스 + 셀/라인 그룹 | 검색 후 선택 |

## 11. 사이드바 배지 · 진행률

| 조건 | 표시 |
|---|---|
| 로봇 관리 배지 | "가동 M/전체 N" 형식(총대수 단독표시 금지) |
| 명령 진행 중(지연 없음) | 3단계 체크리스트 `동작 준비 → 안전 규칙 확인 → 가상 동작 확인`에서 현재 단계만 진행중 표시, 완료단계는 체크, 미시작단계는 중립색 |
| 위 3단계가 임계시간 초과 지연 | 세부 단계명 + 경과시간 펼침 표시 |
| 질문(ASK) 발생 | 체크리스트 대신 정보입력 요청 화면으로 전환(0~N회 가능), 답변 후 "동작 준비"부터 재개 |
| 차단(BLOCK) 발생 | 실행불가 통보 화면(원인·수정방법), "명령 수정"/"새 명령 입력"만 허용 |
| 3단계 모두 통과 | "실행 전 최종점검" 카드로 전환(유일한 승인 지점) — 대상로봇·도구·출발지·목적지·영향구역·안전확인결과·검증시각 표시 + "이대로 실행" 버튼 |
| 최종점검 승인 후 계획/안전상태 변경 감지 | 승인 즉시 무효화, 재검증·재승인 요구 |

## 12. 로봇관리 — 운용가능 여부(결과값, 토글 아님)

| 조건 | 표시 | 허용행동 |
|---|---|---|
| 안전검사 통과 AND 연결정상 AND 도구적합 | "운용 가능" | 명령 대상으로 선택 가능 |
| 안전검사·연결·도구적합 중 하나라도 실패 | "운용 불가 — {실패 사유}" | 명령 대상에서 자동 제외, 사유 클릭 시 상세 |
| 관리자가 "사용 중지" 승인 처리 | "관리자 중지" (일반 상태와 구분되는 별도 배지) | 안전검사 결과와 무관하게 명령 차단, 재개는 관리자 승인 필요 |
| 위 어느 것도 아님(초기/미등록) | "미등록" | 명령 대상에서 제외 |

주의: 작업자 화면에는 활성/비활성 스위치를 두지 않는다. "운용가능"은 항상 상태 검사의 결과이고, "관리자 중지"만 사람이 직접 바꾸는 유일한 수동 상태다.

## 14. 기록 — 필터 축 분리(검증결과 vs 실행결과)

| 축 | 값 | 의미 | 같이 쓸 수 있는 축 |
|---|---|---|---|
| 검증결과(A) | 안전확인됨/실행차단/추가확인필요 (내부값 PASS/BLOCK/ASK) | 시뮬레이션·안전규칙 검사 결과 | 실행결과(B), 로봇, 날짜 |
| 실행결과(B) | 성공 / 실패 / STOP | 실제 로봇 동작 결과 | 검증결과(A), 로봇, 날짜 |
| `A = BLOCK` | — | 실행결과(B)는 항상 "해당없음"(실행 자체가 발생 안 함) | 실행결과 필터 자동 비활성화 |
| `A = PASS` AND `B = STOP` | — | 실행 중 정지 발생 | STOP 사유·요청자 함께 표시 |
| 명령 1건 타임라인 펼침 | 계획→시뮬레이션→권한→실행→정지 순으로 각 단계의 A/B 값 표시 | — | — |

## 15. 진단 — 서비스 헬스(System status 위젯 드릴다운)

| 조건 | 사이드바 위젯 표시 | 진단화면 상세 표시 | 허용행동 |
|---|---|---|---|
| 서비스 정상(ROS2/PLANNER/SAFETY PLC/LATENCY 모두) | 녹색 4행 | 최근 점검시각·정상 이력 | 전체 기능 정상 |
| 특정 서비스 경고(지연 임계 근접 등) | 해당 행 황색 | 원인·최근 실패 이력·관련 시스템이벤트 | 신규 명령에 지연 가능성 안내 표시 |
| 특정 서비스 장애 | 해당 행 적색 | "문제 – 영향받는 기능 – 조치" 형식으로 표시(예: "새 명령의 동작계획을 만들 수 없음", 서비스명은 기술정보로만) + 진단자료 내보내기 버튼 활성 | 해당 서비스 의존 기능(예: 계획생성 서비스 장애 시 신규 계획생성) 차단 |
| 로봇 상태 원시 샘플 조회 | — | 문제 감지 시에만 펼침, 평상시 숨김 | 관리자·엔지니어만 조회 |

## 17. 설정 — 안전임계값 변경 상태머신

| 내부 상태 | 화면 표시 문구 | 의미 | 다음 전이 조건 |
|---|---|---|---|
| `초안` | 작성 중 | 안전관리자가 새 임계값 입력, 변경사유 필수 기재 | 제출 시 `검증대기`로 |
| `검증대기` | 검사 중 | 규칙엔진 시뮬레이션으로 기존 봉인세트 재실행 | 통과 시 `승인대기`, 실패 시 `초안`으로 반려 |
| `승인대기` | 승인 필요 | 2차 승인자 검토 | 승인 시 `적용예정`, 반려 시 `초안` |
| `적용예정` | 적용 예약 | 적용 시각 예약(즉시저장 금지) | 예약시각 도달 시 `적용됨` |
| `적용됨` | 사용 중 | 실사용 중, 버전 기록 확정 | 새 변경 시작 시 새 `초안` 생성(기존 값은 이력으로 보존) |
