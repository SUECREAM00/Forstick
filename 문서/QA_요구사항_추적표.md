## 검사 방법 기호
| 기호 | 뜻 |
|---|---|
| UI | Playwright로 `dashboard2` 화면 자동 검사. 서버 응답은 가짜로 대체(서버 없이 결정적) |
| API | 작업 셀 서버에 직접 요청(읽기 + 로봇이 움직이지 않는 명령만). 서버가 꺼져 있으면 **미실행** |
| BE | 기존 백엔드 단위·통합 테스트(`tests/`)를 실행만 해서 대응(백엔드 코드는 고치지 않음) |
| 측정 | 실제 로봇 동작·평가셋 실행이 필요한 수치 지표. 자동 판정하지 않음 |
| 결정 | 기준이 엇갈리거나 로봇을 움직여야 해서 사용자 결정이 먼저 필요 |

## 6. 결정 필요 (사용자 판단 전에는 판정하지 않음)
| 번호 | 내용 | 왜 결정이 필요한가 |
|---|---|---|
| D1 | 요구사항 기준: 기획서(UR5e+FR3 2종 · 루시아 LLM · PWA)인가, 지금 구현(FR3 1종 · Qwen3 · React 대시보드)인가 | 기준에 따라 SFR-004·013, NFR-009, TER-003의 판정이 달라진다 |
| D2 | 대시보드 목업 데이터(지표·로봇 3대·이력·알림)를 실제 서버 값으로 바꿀 범위 | 설계원칙 2 위반이지만, 목록 API가 없어 백엔드 수정이 필요(백엔드 수정 안 함과 충돌) |
| D3 | 시뮬레이션 창 "SIMULATION — 실시간 아님" 표기(화면설계서 ⑧) vs "실제 로봇 아님 표지 넣지 않음"(2026-10-01 결정) | 두 요구가 충돌 |
| D4 | 헤더 버튼 이름 "비상 정지" vs 용어표 "즉시 정지"(UI STOP), "비상정지"는 물리 E-stop 상태 표시 전용 | 용어표 기준이면 지금 문구가 규칙 위반 |
| D5 | 로봇을 실제로 움직이는 검사(E2E·정지 반응시간·성공률)를 팀원 PC에서 돌려도 되는지, 언제 | 팀원 작업과 겹칠 수 있고 자재 위치가 바뀜 |
| D6 | 화면설계서 기능 중 이번 범위(권한·설정 3구역·진단 내보내기·기록 타임라인 등) | 대부분 백엔드 API가 필요 |
